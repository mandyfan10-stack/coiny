# Исправления по аудиту 21 октября 2026

Пакет 1.20.81 включает только согласованные исправления.

Повторная проверка выявила два пропуска в клиенте: подключение ответа на историю и отмена отложенной отправки вложения после выхода. Исправления и результаты проверки описаны в [аудите 22 октября](./AUDIT_2026-10-22.md).

## Поведение клиента

- История, список чатов, предзагрузка и ключи позднего ответа относятся к сеансу аккаунта. Выход сразу скрывает прежнюю переписку; повторный вход не принимает старые обновления.
- Очистка IndexedDB при выходе ждёт завершения удаления. Фоновое сохранение очереди и черновиков не открывает базу повторно во время очистки. Реальная блокировка другой вкладкой возвращает понятную ошибку через пять секунд.
- Ответ на историю отправляется автору в личный чат, при необходимости создаёт его и не меняет активный чат. Успех показывается после подтверждения сервера. При отсутствии сети или сетевой ошибке текст остаётся для повторной попытки, скрытой постановки в очередь нет; обычные сообщения сохраняют прежнюю офлайн-очередь.
- Передаваемый в согласовании звонка тип видео различает камеру и экран, включая замену дорожки без нового события ontrack. Старые клиенты без этого поля поддерживаются.
- Кнопка камеры во время демонстрации действительно включает камеру. Остановка демонстрации во время подключения освобождает захват и сохраняет актуальное состояние.
- Новый участник группового звонка получает актуальное видео при одновременной замене дорожки. Встречные личные вызовы выбирают один вызов на обоих клиентах.
- Кнопка пересылки использует непрозрачный основной цвет темы для контраста текста.

## Сервер

Применены миграции `20261021183411_close_legacy_email_and_attachment_access` и `20261021183422_constrain_membership_insert_roles`:

- Устаревший RPC получения email по username недоступен ролям anon/authenticated.
- Подстановка чужого URL в аватар, историю или сообщение не открывает доступ к чужому вложению. Сохраняется чтение участниками чата и старых аватаров с подтверждённым владельцем.
- Право приглашать участника не позволяет назначать администратора. Существующие роли не изменяются.

Данные миграциями не удаляются. Локальные файлы соответствуют версиям миграций рабочей базы.

Функция `cleanup-orphaned-media` обновлена до версии 4. Она учитывает сырые *_path, URL и канонические ссылки, полностью обходит страницы ссылок и файлов до удаления, прекращает работу при неполном сканировании и сохраняет неоднозначные зашифрованные вложения. Аутентификация и расписание сохранены. Проверка рабочей функции с `dryRun: true` завершилась HTTP 200, completeScan=true, удалено 0 файлов во всех корзинах; 316 непроверяемых вложений сохранены.

## Проверки

- Lint, TypeScript, криптографические тесты, 82 unit-файла и сборка прошли.
- 28 адресных браузерных проверок изоляции аккаунтов и очистки при выходе, а также 20 проверок ответов на истории (включая потерю сети) прошли в Chromium и WebKit на компьютере и телефоне.
- 40 проверок прокрутки и восстановления позиции чтения прошли.
- Обработчик автоочистки прошёл 7 сценариев с тестовыми данными, включая более 1000 ссылок, короткие страницы API, сбои сканирования и dryRun.
- Полный UI, звонки, прокрутка, SQL и live E2E проверяются перед публикацией тега существующим CI/workflow. Итоги выполнения доступны в GitHub Actions.

Первый CI остановил аудит зависимостей из-за уязвимостей Vite 8.2.1. Отдельно согласовано обновление инструмента сборки до закреплённой версии 8.3.5 с повторной проверкой аудита, сборки и UI.

CI коммита a89e65d после обновления Vite прошёл: SQL — 120 проверок, live E2E — 4/4 без повторов, полный UI — 529 passed, 13 skipped, 2 flaky (успех после повтора). В обоих нестабильных случаях WebKit уже заменил видео и передавал аудио, но тестовый перехват replaceTrack на отдельной нативной обёртке не сработал. Перехват перенесён в устойчивый обработчик прототипа тестового окружения; код приложения не менялся. Выпуск 1.20.80 остановлен до публикации для включения этого исправления проверки.

В серии из 60 запусков исправленного теста исходный тайм-аут не повторился: 59 прошли, один завершился `Target crashed` при ожидании подключения третьего участника. Трасса сохранена; причина аварии процесса тестового WebKit не установлена. Этот результат не считается полностью успешной серией и не доказывает неисправность клиентского JavaScript.

Отдельная серия с журналом браузерного процесса: 10/10 WebKit desktop без повторов и аварий. Исходная неуспешная трасса не удалена; окончательный результат пакета проверяется полным CI и релизным workflow.

Браузерные проверки используют синтетические устройства захвата; они не заменяют проверку на физических Android/Windows и в реальной Wi-Fi сети пользователя. Уменьшение задержки для конкретного маршрута в России не измерено; отсутствие будущих разрывов не гарантируется.
