# Интерфейс Coiny

Основой оформления служат Telegram Desktop и классическая боковая навигация
Telegram для Android. Визуальные изменения собираются из общих компонентов,
без замены обработчиков сообщений, настроек и звонков.

## Общие правила

- Палитры, системный шрифт, цвета сообщений и длительность переходов находятся
  в `src/styles/tokens.css`. Сохраняются все шесть идентификаторов тем.
- `--accent-solid` используется для кнопок с белой надписью, `--accent-color` —
  для текста и значков. Это разные цвета, чтобы сохранить контраст.
- Кнопки со значками имеют область нажатия 44 × 44 px. Общие `IconButton`,
  `Button`, `SearchField`, `Switch` и `Avatar` находятся в `components/ui/`.
  Они используют нативные элементы и сохраняют переданные события и ссылки.
- Поверхности однотонные. Разделители и отступы показывают структуру экрана;
  светящиеся рамки, декоративное размытие и увеличение карточек не нужны.
- До 768 px используется один основной экран, боковое меню и полноэкранные
  настройки. Учитываются безопасные области и низкая высота окна.
- Уменьшенное движение отключает декоративные переходы. Длительность истории,
  запись аудио и другие функциональные таймеры продолжают работать.

## Где менять оформление

| Экран | Владелец стилей |
|---|---|
| Основная раскладка | `styles/messenger.css` |
| Список чатов | `components/Sidebar.css` |
| Шапка и история чата | `components/ChatArea.css` |
| Ввод сообщения | `components/chat/ChatComposer.css` |
| Поиск и панель медиа | `components/chat/ChatSearchBar.css`, `MediaPickerPanel.css` |
| Просмотр медиа | `components/chat/ImageViewer.css` |
| Мобильные действия сообщения | `components/chat/MobileActionSheet.css` |
| Настройки и превью профиля | `components/settings/SettingsDialog.css`, `ProfilePreview.module.css` |
| Информация о чате | `components/ChatInfo.css` |
| Меню, вход и создание чата | CSS-файл рядом с соответствующим компонентом |
| Истории | `components/Stories.css` |
| Шифрование и обновление приложения | CSS-файл рядом с соответствующим компонентом |
| Звонки | `components/call/CallOverlay.css` |

Новые правила следует добавлять в файл владельца экрана. В `index.css` остаются
общие и прежние правила; новые глобальные переопределения компонентов туда
не добавляются. Правила настроек ограничиваются `.settings-dialog-overlay`.

## Проверка

`tests/ui/interface-fixture.html` показывает реальные компоненты с локальными
данными. Фикстура не требует аккаунта. Параметры `?list`, `?surface=auth`,
`?surface=setup`, `?surface=unlock` и `?surface=update` открывают отдельные экраны.

`interface-redesign.spec.mjs` и `secondary-interface.spec.mjs` проверяют размеры
320, 390, 768, 1024 и 1920 px, низкую высоту, обе палитры, управление с клавиатуры
и сохранение основных действий в Chromium и WebKit. Остальной набор UI-проверок
сохраняет сценарии реакций, поиска, истории и автоматического сохранения.

Перед тегом релиза обязательны lint, typecheck, unit-тесты, сборка,
`npm run test:ui`, `npm run test:scroll` и E2E. Существующий workflow выпуска
дополнительно проверяет взаимодействие двух реальных тестовых пользователей,
подпись APK и Windows-пакет.
