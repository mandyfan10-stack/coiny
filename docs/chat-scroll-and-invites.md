# Прокрутка чата и приглашения

## Что изменено

- Строки сообщений измеряются по фактической высоте. Убраны `content-visibility: auto` и приблизительная высота 60 px, которые оставляли длинный чат выше последнего сообщения и сдвигали восстановленную позицию.
- Привязка к последнему сообщению сохраняется при загрузке изображения, изменении размера окна и поля ввода. Событие прокрутки от браузерного изменения геометрии не снимает эту привязку. Колесо, касание, полоса прокрутки и клавиатура позволяют перейти к чтению истории.
- Запрос старых сообщений связан с конкретным открытием чата. Переключение A → B → A не возвращает старому запросу право менять прокрутку. Пока запрос выполняется, пользователь может перейти к другому сообщению; после ответа сохраняется новая позиция.
- При выходе сохраняются сообщение и его положение на экране, включая последний шаг до события `scroll`. Эта позиция имеет приоритет над новыми непрочитанными сообщениями. Если начальная загрузка не содержит нужного сообщения, история подгружается до него; при сетевом сбое исходная позиция остаётся сохранённой. Для удалённого сообщения восстанавливается соседнее место по времени.
- Восстановление после подгрузки выполняется после обновления DOM в `useLayoutEffect`. Промежуточное браузерное событие при добавлении строк сверху не заменяет выбранное сообщение новой первой строкой.
- Закрытая панель информации не создаёт приглашения. Новые сообщения не вызывают повторную генерацию ссылки. Обычному участнику показывается предложение запросить ссылку у администратора, а ошибка создания отображается в панели.

## Проверка прокрутки

```bash
npm run test:scroll
```

Playwright запускает отдельный mock-сервер и настоящий `ChatArea` с управляемыми ответами истории. Проверяются desktop 1440×900 и mobile 390×844: открытие 200 сообщений, пять переключений диалогов, перезагрузка страницы, изменение высоты строк, задержанная загрузка изображения, изменение высоты окна, клавиатура и запоздалые ответы пагинации. Сервер принудительно использует mock-режим, даже если в `.env` указан Supabase. Проверки включены в CI и проверку релиза.

## Миграция приглашений

`supabase/migrations/20261006062312_sync_secure_chat_invites.sql` восстанавливает `create_chat_invite` и `join_chat_by_invite`, ограничивает создание приглашений владельцем/администратором и запрещает назначить себе администратора при прямом вступлении. Токены имеют срок действия, хранятся как SHA-256 и проверяются под блокировкой строки. UUID чата не является приглашением. Доступ `anon` и `authenticated` к RPC, возвращавшему email аккаунта, отозван.

Миграция проверена двумя способами: полный сброс локальной базы со всей историей миграций и отдельное применение поверх схемы до `20260827130000`, в которой ещё отсутствуют сентябрьские RPC. Она не требует менять исторические timestamps миграций на сервере.

```bash
npx supabase start
npx supabase db reset --local --no-seed
npx supabase test db supabase/tests --local
npx supabase db lint --local --level warning --fail-on warning
```

Релизный workflow по тегу развёртывает веб-клиент и публикует APK/Electron. Он не применяет миграции к hosted-проекту. Перед обновлением hosted-базы следует проверить вход тестовых пользователей с текущим клиентом: старый публичный resolver email теперь недоступен. При расходящейся истории миграций для восстановления приглашений можно применить эту самостоятельную миграцию, не переигрывая старые миграции.

Проверки реализации: 528 unit-тестов и криптографическая проверка E2EE, 38 сценариев прокрутки, 11 mock UI-сценариев, проверка безопасности Electron и 71 SQL-проверка. Lint, typecheck, сборка и проверка версии релиза проходят; локальный security advisor не сообщает проблем. Live-сценарии звонка, прочтения и реакций прошли в CI на GitHub. Android APK локально не собирался: Android SDK в окружении не настроен.

При подготовке релиза обнаружена дополнительная гонка: начало движения вверх на 1–15 px снимало признак ручного чтения, и следующее сообщение возвращало чат вниз. Возврат к нижней границе теперь учитывает направление движения, а округление при восстановлении позиции не считается ручным движением вниз. Проверка малого первого шага входит в браузерный набор.

## Зависимости

Capacitor обновлён согласованно до 8.5.2, Electron — до 43.7.7. Исправленные транзитивные версии закреплены в `overrides`. Для `global-agent` используется 4.1.3 с совместимым `bootstrap()`; это убирает уязвимую цепочку `roarr` → `sprintf-js`, сохраняя загрузчик Electron Builder. `gh-pages` закреплён на 6.1.1, поскольку 6.3.0 подтягивает `braces`, для которого на момент проверки нет исправленного релиза. Совместимость CLI и загрузчика проверена; полный `npm audit` и аудит runtime-зависимостей не находят уязвимостей.
